# Acceptance cases for the proposed Trace implementation

These are required future acceptance cases, not newly authored production tests and not claims of passes in this review. Opus 5.5 owns browser/UI tests; Astra owns backend/resource tests. Use public synthetic or already-approved fixtures for development. Private originals, aliases, screenshots, logs, and identifiers stay local.

The tests should establish observable behavior and data invariants. Do not merely assert that the implementation called its own helper. Keep a small set of meaningful rendered scenarios in addition to pure data tests; fake-DOM Node tests cannot prove focus retention, WebGL geometry, touch operation, or layout.

## A. Identity, integrity, and coverage

| Case | Setup | Pass condition |
| --- | --- | --- |
| A01. Qualified duplicate IDs | Two environments have the same raw T3 thread ID; both have runs, native bindings, and an exact relationship. Give both environments the same display label as well. | Both threads and their bindings remain distinct through load, filter, selection, search, own-session open, parent traversal, history, notes, and citation resolution. Copy returns the original ID; labels distinguish the entries. No first-match merge. |
| A02. Manifest authority | A manifest declares a gzip member while a stale plain twin exists, then reverse the transition. Test helper-served and dropped-directory entry paths. | Both paths use declared bytes. Logical listings contain one member. A missing declared member, digest/size mismatch where recorded, or unreadable manifest does not fall back to the twin. |
| A03. Legacy ambiguity | Open a legacy bundle with one representation, then both representations without authority. | The single-member case follows a documented compatibility path. The ambiguous case identifies the problem instead of using mtime or plain-first preference. |
| A04. Interrupted receive | Interrupt after replacing one file but before publishing the rest of the manifest generation. Include a same-size changed file. | The receive journal/generation contract prevents assembly or cache reuse as a coherent fresh snapshot. A previously validated generation may remain usable with its original identity and coverage. |
| A05. Generation during lazy reads | Issue a source ticket, replace its underlying path, then request another range; also refresh during a browser source open. | Reads remain on the immutable ticket generation or fail with explicit invalidation. No mixed-source reader and no old result installed into the new selection. Same-size replacement does not evade validation. |
| A06. Root unreadable, child readable | Preserve root metadata and a valid child transcript, with a precise root parse failure. | Family opens with the readable child and known root in inventory; no invented root request, height, parent call, or successful-empty status. |
| A07. Metadata-only and untimed | Family has only void/provider-event/metadata records, including a point event and a timestamp-free thread. | Every known thread is inspectable. Point events are represented without fake duration. Untimed entries remain in the list. No NaN/Infinity geometry; Play has no fabricated duration. |
| A08. Native mapping ambiguity | Two native agents share a title; one known provider-native thread has no exact reference and another has an exact reference. | Exact match is retained. Title-only candidates remain inferred/ambiguous; an unmatched thread is not dropped because its ancestor has a ridge. |
| A09. Multiple native bindings | One T3 thread continues in distinct sessions/products. Open its later ridge and choose its own session. | The exact clicked binding opens, including correct source set, product/version, and Back to the same family selection. The thread's primary binding is not substituted. |
| A10. Join provenance and routes | Include lineage, delegatedFrom/remoteChild, authoritative creation-item joins, transcript call/result fallback, direct/SSH/Cloudflare route evidence, and unrelated overlapping work. | Only supported qualified joins establish membership. Each join retains its actual source. Route evidence neither fabricates a calling thread nor changes physical-machine counts. |
| A11. Honest delivery and silence | A disposed result lacks comparable completion times; a log is absent in one case and quiet in another; a request remains open across a log gap. | UI and AI packet state disposition and bounded log coverage. They do not assert late completion, inactivity, or missing execution without the relevant evidence. |
| A12. Complete note catalog | More than 200 warnings/explanations, repeated conditions, duplicate-looking labels, and legacy untyped notes. | Group counts reconcile to stored occurrences. Every original explanation is reachable through pagination/search/reader. UI and helper do not silently slice the tail. |

## B. Playback, inspection, and concurrency

| Case | Setup | Pass condition |
| --- | --- | --- |
| B01. Delegate-only tail | Root has one request; a delegate starts later and records requests/end events an hour beyond the root. Repeat with no readable root requests. | Family clock spans all finite family evidence. Play, scrub, comma/period, and transport End reach the delegate tail. Scene clipping and readout agree in 3D and 2D; reaching the root's end does not reveal future delegates. Adding event/request records without changing the domain does not change the proposed base sweep duration. |
| B02. Simultaneous timestamps | Several agents have requests/events at the same timestamp. Include raw clock regression and explicit uncertainty on another environment. | Event stepping visits the timestamp group once and makes all members inspectable. Request navigation still visits each selected agent's source order. No artificial timestamp offsets or hidden claim of causal ordering. |
| B03. Stable reader during playback | At least sixteen overlapping agents. Open exact text, select text, scroll, place keyboard focus on an action, then explicitly Play for at least 100 ticks. | Underlying selection, reader DOM identity, selected text, scroll, and focus remain intact. No map-center or active-agent replacement, no closing a deep reader to start playback. |
| B04. Manual camera ownership | Enable family follow, pan/zoom, pause and Play; later choose named-agent follow, then inspect another agent. | Manual gesture disables follow. Play does not re-enable it. Named target remains the chosen key until explicitly changed. Neither action selects inspector content. |
| B05. Activity choice | Open activity during dense concurrent work with known intervals, point-only events, waits, and unknown state. | Opening pauses and freezes the cursor-specific list. Stable order/focus; no busiest-agent reshuffle. Choosing a row preserves family time and selects only a uniquely justified request, otherwise its overview. Completed intervals use the documented boundary; point-only and unknown work do not become continuous execution. Counts deduplicate agent keys and distinguish threads without native agents. Back restores the previous reader and invoking-control focus. |
| B06. Selection and filters | Select an agent/request, filter its environment out, then clear or explicitly reveal it. | Selection and global clock domain are unchanged. Filter state is visible and reversible; scope used by AI does not silently narrow. |
| B07. Keyboard ownership | Exercise transport, selected request navigation, reader text, input, menus, palette, and range endpoint fields. | Comma/period step family events only in playback context. Arrows/Home/End respect focused scope. Space preserves reader scrolling and button activation. Inputs never trigger playback/agent navigation. |
| B08. 2D and reduced motion | Force WebGL failure and reduced motion independently. | Existing fallback opens; source reading, activity discovery, family transport, stepping, search, copies, custody, and AI remain usable. No hidden WebGL requirement; no involuntary camera animation. |
| B09. Async open race | Start a ladder/source/own-session open, then choose different evidence or another family. Delay old completion and inject worker failure. | Every pending promise settles once; old completion cannot replace current content. Correct current action remains usable. Test load, text, body, fleet, provenance, and search classes. |
| B10. Lazy bounds and history | Attach/query network evidence with an event outside the current declared clock domain; navigate reader/citation/Back. | Any domain extension is explicit and does not move selection/cursor unexpectedly. Back restores exact evidence and position on the same generation; stale anchors are never rebound to new bytes. |

## C. Surface reduction and retained capabilities

| Case | Setup | Pass condition |
| --- | --- | --- |
| C01. Removed Harness entry | Initial open, old saved Harness mode, old URL/history value, `h`, palette, and narrow menus. | Landscape or fallback opens. No separate Harness GUI/action/shortcut remains. Unrelated source evidence and strata remain. |
| C02. Provenance without GUI | On both products and a mixed-provider family, traverse copies with keyboard and palette, open source references and custody, then Back. | Lazy service works without a Harness host or WebGL. Correct native product/version source index and exact anchor are used. Missing reference coverage is stated, not borrowed from root. |
| C03. Capture actions | No capture, recording, stopped/unattached, helper unavailable, and already-running application states. | Initial surface exposes Record, Open file, Help plus minimal status. Each action performs the named supported operation or reveals its single relevant setup step. No automatic app termination; no command before the relevant choice. |
| C04. Identifier collisions | Long encoded IDs, same-prefix/suffix hashes, URLs with similar paths, duplicate titles, Unicode, and invalid percent escapes. | Ordinary labels remain distinguishable, stable, short, and safely decoded. Reveal works on keyboard/touch; separate Copy produces the full exact original. Narrow expansion does not widen the page. |
| C05. Void and break inspection | Use only keyboard, then touch, to reach a void, metadata-only item, disposed delivery, and uncertain relationship. | Same exact explanation/evidence is reachable as with pointer hover. No fake request zero or empty reader trap. |
| C06. Narrow/zoom operation | 360px, 390px, 768px, 980px boundary, desktop, 200% zoom, and on-screen keyboard. | Capture/Help/search/lenses/transport/Back/Send remain reachable; no overlapping fixed bars or clipped main action; reader can expand to usable height; focus stays visible. |
| C07. Text-density audit | Walk loader, overview, agent/request/source, network, capture, notes, Help, progress/error, and AI. | Routine paragraphs are removed by better controls/state. Moving the rejected capture essay into an expander fails. Exact evidence and every original explanation remain deliberately accessible. |

## D. AI contract and evidence quality

| Case | Setup | Pass condition |
| --- | --- | --- |
| D01. No implicit egress | Open a family, source, composer, scope picker, and preset; edit a question; prepare locally. Record mock endpoint traffic. | Zero provider/model-discovery requests until the corresponding explicit check or Send. Send names the frozen scope, destination, and model. |
| D02. Scope construction | Exact item; request; typed inclusive range; multiple layers; native agent; continuing T3 thread; causal path; family; scoped network. | Prepared identity/counts match selection, including endpoints/facets. Visible filters are not implicit scope. Cross-session ordinal ranges are not fabricated. |
| D03. Balanced whole family | Large first agent plus small agents across four environments, an unreadable root, missing natives, and more total text than the cap. | Inventory accounts for every known qualified entity before excerpts. Included/omitted/unreadable coverage is per-entity. Excerpts do not silently represent only the first agent. Inventory over cap requires explicit narrowing or disclosed aggregate-only scope. |
| D04. Frozen preview | Edit question, model, endpoint, key revision, scope, or generation after preparing; expire preview; race two Sends and replay its token. | Old preview rejected before provider egress. One atomic consumption creates at most one request. No hidden retry, failover, or replacement model. |
| D05. Cancel and stream ownership | Cancel during connect/headers/deltas; load a new family; start a new run; deliver delayed events and duplicate terminal messages. | Upstream abort attempted; one terminal outcome per run; late old events ignored. Partial answer remains incomplete. Cancellation does not claim previously sent bytes were retracted. |
| D06. Input/output limits | At/beyond each declared cap, very long line, oversized model list/error body, malformed UTF-8/JSON, invalid/truncated SSE, unsupported content type, slow headers/body, redirect. | Finite resource use and actionable bounded error. No arbitrary fetch proxy, redirect following, credential leakage, partial-success mislabel, or automatic resend with truncation. |
| D07. Credentials and origin | Invalid key, unavailable loopback proxy, hostile origin, URL userinfo/query credential, changed destination, provider error echoing input. | Configured-handle/origin protections hold. Keys remain memory-only and absent from logs, URLs, evidence, exports, saved state, and surfaced errors. Failure does not disable unrelated source reading. |
| D08. Citation adversary | Unknown/duplicate/malformed IDs, forged URL, HTML/script, instruction-like log text, valid ID attached to an unsupported claim. | Only IDs in the frozen map navigate. No execution or arbitrary local/network link action. Validity is not presented as claim verification. Unsupported inference remains reviewable and identified. |
| D09. Capture-stage comparison | Native reconstructed prompt and on-wire payload differ; repeat with two comparable on-wire requests and with redacted fields. | Local first-difference calculation preserves stage/provenance and exact anchors. Cross-stage differences are not labeled proven mutations; redacted fields are not treated as equal. |
| D10. Delivery versus consumption | Worker transcript, handback report, status-only message, and later parent request are independently present/absent. | Packet and answer distinguish execution, delivery, and parent consumption. A last assistant message, stop event, or disposed result is not substituted for another stage. |
| D11. Citation reader/Back | Open several answer citations while playing, use Back, change ordinary selection, then release the source generation. | Answer/question remain stable. Reader pauses follow/playback on entry. Same-generation navigation restores position; released-generation anchors explicitly fail instead of rebinding. |
| D12. Small interaction | Keyboard and touch range/layer/path selection, editable preset, destination setup, Send, Cancel, error retry, and answer reading at narrow width. | No generic single-agent-only limitation, developer JSON wall, compulsory extra preparation wizard, hidden scope change, or inaccessible primary action. |

## E. Resource and final local acceptance

| Case | Required measurement or check |
| --- | --- |
| E01. Repeated native access | Count decompressions/reads per immutable member across multiple bindings and own-session opens. Demonstrate removal of repeated environment-wide rollout decompression without unbounded retained expanded bytes. |
| E02. Network ownership | Demonstrate no span derivation on normal/non-network inspection. Measure/cancel first derivation, retry after failure, reuse within its generation, and release after family switch. If precompute is consumed, verify a versioned parity contract before claiming equivalent results. |
| E03. Offset and privacy invariants | Compare streamed span/index results and exact source offsets against approved fixtures, including compressed members and longest supported lines. Preserve redaction/privacy scan behavior and account for rejected/omitted records. |
| E04. Controlled performance | Use identical recorded generation and normal Node heap for before/after comparisons. Record wall time, peak heap/RSS, input counts/bytes, scope, cache state, and versions. Do not treat the supplied older smaller baseline as a controlled speed comparison. |
| E05. Complete repository gate | Run `npm run check` in a proper local checkout with required tools. Record the exact exit and any failures. A passing selected test suite does not stand in for build, all tests, link checks, and leak checks. |
| E06. Rendered verification | Capture local rendered evidence for the core 16-agent reader scenario, tail playback, rootless/void inspection, removed Harness/provenance, capture, narrow layout, and AI mock navigation. Distinguish actual browser execution from source inspection and fake-DOM tests. |
| E07. Private final family | Perform a fresh ordinary resolver refresh of the latest Scan-to-Make / Counterpart family, reconcile source inventory, thread rows, native bindings, drawable agents, and explicit missing/unreadable entries. Inspect latest continuations and all environments. Counts are dynamic; do not hard-code the older 55-thread checkpoint. |

Acceptance is complete only when the data reconciliation, full gate, rendered interactions, mandatory AI scenarios, and private family result are reported together with any remaining limitations. Counterpart is the companion app; do not describe it as a T3 fork. Publish only approved public code/documentation, not the private acceptance material.
